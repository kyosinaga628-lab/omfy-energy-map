How it works.

全体の仕組み

データの置き場所は Google スプレッドシート 1 つだけです。フォームもサイトも Kumu も、このシートを読み書きしています。

01 書く

フォーム・シート

サイトの「この論点に意見を書く」から Google フォームで。シートに直接書いてもよい

02 ためる

スプレッドシート

「意見」「論点」「属性マスタ」など 8 枚のシート。データの正本はここ

03 公開する

公開 CSV

3 枚のシートを自動で CSV として公開。手作業はいらない

04 見る

サイト・Kumu

俯瞰ビュー・詳細ビュー・Kumu が開くたびに読み込む。GitHub に毎晩控えを保存

どこまで反映にかかる時間の目安
フォーム → シート送信して数十秒以内に「意見」シートの末尾に 1 行入る
シート → サイト・Kumu数分（長いと 5 分ほど）。そのあとページを再読み込みすると出る
新しい論点・ハンドル → フォームの選択肢1 時間以内（自動更新）。急ぐときはモデレータが手動で更新
GitHub の控え（スナップショット）毎晩 3 時（日本時間）。変化があった日だけ記録される

Rules.

みんなのルール

シートとサイトは一般に公開されています。書いたものは誰でも読めて、再利用もされます。

書かないこと

  • 実名、連絡先、学校名、住んでいる地域など、個人が分かること（自分のことも、他人のことも）
  • 会合に出た人・講師の実名。「ゲストの講師」「参加者の一人」のように書く
  • 他の人の行の書き換え・削除
  • 特定の人や団体への攻撃。意見には意見で応える（相手の行ではなく、同じ論点に自分の意見を書く）

知っておくこと

  • 書いた人の名前は出ません。当面は全員が共通のハンドル「omfyメンバー」で書くので、誰が書いたかもサイトからは分かりません
  • いまはメンバーだけが書き込めます。のちのちは誰でも書き込めるようにする方針です。広げる前に、公開前の確認や荒らしへの対策を整えます
  • 書いたものは CC BY 4.0（出典を示せば誰でも再利用できる）で公開されます
  • 意見は書いた人個人の見解で、omfy の公式見解ではありません
  • 中学生・高校生は、参加の前に保護者の同意が必要です
  • 消した意見も、GitHub の毎晩の控えに過去の版が残ります。完全に消す必要があるときは削除の申請へ
Member.

メンバー編：意見を書く

意見は 1 件ずつ、論点マップの論点のどれか 1 つに付けます。書き方はフォームとシートの 2 通りで、どちらで書いても同じ「意見」シートに入ります。

はじめに：ハンドルは「omfyメンバー」を選ぶ

当面は、メンバー全員が共通のハンドル omfyメンバー で書きます。個人のハンドルネームの登録はいりません。

  1. Google アカウントを用意するフォームは Google アカウントでのログインが必要です。シートの共有に使ったアカウントで構いません。
  2. 意見を書くとき、ハンドルの欄で omfyメンバー を選ぶフォームでもシートでも、▼の候補から選べます。

個人のハンドルを使えるようにするときは、あらためて案内します。

書き方 1：サイトからフォームで書く（おすすめ）

スマートフォンでも書けます。論点が最初から選ばれた状態でフォームが開くので、選び間違いがありません。

  1. 詳細ビューか俯瞰ビューで、意見を書きたい論点を選ぶ
  2. 論点の欄にある この論点に意見を書く を押すGoogle フォームが別のタブで開きます。初回は Google へのログインを求められます。
  3. ハンドル・記入者属性・立場・根拠タイプを選び、主張を書く選び方は下の「各項目の選び方」へ。
  4. 送信する数分後、サイトのページを再読み込みすると地図に出ます。

論点が決まっていなくても、意見フォームを直接開いて、フォームの中で論点を選べます。

書き方 2：スプレッドシートに直接書く

パソコンでまとめて書くときに向いています。

  1. 共有された「omfy 論点マップ（公開用）」を開き、下のタブで「意見」シートを選ぶ
  2. いちばん下の空いている行に、1 件 1 行で書く記入日は、書き始めると自動で入ります。
  3. ハンドル・論点・記入者属性・立場・根拠タイプは、セルの▼から選ぶ一覧に無い値は入力できません。
  4. 主張を書く。長くなったら「補足・出典」の欄へ主張が 200 字を超えたり、必須の欄が空いていたりすると、セルが赤くなります。

シートのタブは「意見」以外は触らないでください（論点の追加はモデレータが行います）。主張を = や - で始めると数式として扱われることがあります。そのときは先頭に '（半角のアポストロフィ）を付けてください。

記入者属性（14）

同じ人でも、家庭で電気を使う立場で書く日もあれば、学生として書く日もあります。その意見を書いたときの立場を選んでください。

書き方の例

伝わりやすい

論点「安定供給」／立場「条件付き」／根拠「データ」

「再エネを増やすなら、蓄電池と送電網の増強を同じ計画で進めるべきだ。そうでなければ、晴れの日の余りと夜の不足を埋められない。」

条件（何がそろえば賛成か）がはっきりしている。補足に出典を書けばさらに良い。

伝わりにくい

論点「エネルギー」／立場「反対」

「今のやり方はおかしいと思う。もっとちゃんと考えるべき。」

何に反対なのかが分からない。もっと具体的な論点を選び、何がおかしいのかを一つに絞って書く。

書いた意見を直す・消す

  • 直す: 「意見」シートで自分の行を直接直してください。ハンドルは全員同じ「omfyメンバー」なので、記入日と主張の文面で自分の行を探します。フォームから送った意見も、シートの行を直せば反映されます。
  • 消す: モデレータに連絡してください（行を消すと、他の人の行を巻き込む事故が起きやすいため）。
  • 間違えて他の人の行を変えてしまった: すぐに Ctrl+Z で戻すか、モデレータに連絡してください。シートの「ファイル → 変更履歴」から元に戻せます。
Moderator.

モデレータ編：論点を整える

モデレータは、地図の骨組み（論点）を整え、意見がルールに沿っているかを確かめます。意見の中身の良し悪しは判断しません。

日々の点検（週に 1 回が目安）

  1. 詳細ビューの「データの点検」を開く親が見つからない論点、名前が重なる論点、論点名がずれた意見などを警告します。警告が 0 件なら問題ありません。
  2. 「意見」シートで赤いセルを探す主張が 200 字超、または必須の欄（ハンドル・論点・属性・立場・根拠タイプ）が空です。書いた人に知らせるか、明らかな誤りなら直します。
  3. 新しい意見を読み、ルール違反（実名・連絡先・攻撃など）が無いか確かめる確かめた行は「モデレータ確認」列を 済 に。直してほしい行は 要修正 にして、書いた人に連絡します。
  4. 詳細ビューの「抜けの確認」で、意見の少ない論点・立場を見る会合で「この論点に、この立場の声がまだ無い」と呼びかける材料にします。

ハンドルの扱い

当面は、メンバー全員が共通のハンドル omfyメンバー で書きます。個人のハンドルの登録は受け付けていません。

ハンドル使う人フォームで選べるか
omfyメンバーメンバー全員選べる
omfy過去の議論（-2026/10）モデレータ（過去の会合の議論を起こすとき）選べない
ゲスト意見モデレータ（ゲスト・講師の話を起こすとき）選べない

全員が同じハンドルなので、シートやサイトからは誰が書いたか分かりません。直してほしい意見があるときは、メンバー全体に「○月○日の、○○という意見を書いた方へ」と呼びかけます。フォームから書いた意見は、フォームの回答の控え（共有アカウントだけが見られる）にログインしたアカウントが残ります。

個人のハンドルを使えるようにするときは、会員名簿（非公開）に実名とハンドルの対応を書き、「選択肢」シートの E 列にハンドルだけを足して、omfy → 6. 意見フォームの選択肢を更新 を実行します。

論点を足す・まとめる・分ける

「論点」シートで 1 論点 1 行です。行は消さず、要らなくなった論点は「状態」を変えます。

列書き方
ID英小文字とピリオド。親の ID に続ける（例: 原子力の下なら nuc.backend）。一度決めたら変えない（サイトのリンクに使うため）
論点名20 字以内の名詞句。他の論点と同じ名前にしない（意見はこの名前で論点に結び付く）
種別目的（目指す社会）／テーマ（エネルギーなど）／評価軸（S+3E、議論の視点）／対象（原子力などの電源・技術・個別の課題）／問い（さらに細かい問い）／外部環境（国際情勢などの前提）
親論点▼から既存の論点名を選ぶ。「目的」以外は必須
安全性〜環境適合関係する S+3E の評価軸に ○
問い「〜か」で終わる問いにする（例: 核融合をどう位置づけ、どこまで投資するか）
状態案／確定（会合で合意したら）／統合済／取り下げ。統合済・取り下げの論点はフォームの選択肢とサイトのボタンから消える
  1. 「論点」シートのいちばん下に行を足す（まとめる・分けるときは、該当する論点の状態を変える）
  2. まとめる・分けるときは、「意見」シートで付け替えが必要な意見の「論点」列を新しい論点に変える
  3. 「変更履歴」シートに 1 行書く日付・対象（論点名）・変更内容・理由（一行）・実施者・承認者。
  4. すぐ反映するなら omfy → 3. Kumu 用の数式を再生成 を実行Kumu とフォームの選択肢が一緒に更新されます。しなくても 1 時間以内に自動で反映されます。
  5. 詳細ビューの「データの点検」で警告が出ていないか確かめる

論点名を変えると、その論点に付いた意見が結び付かなくなります（意見は論点名で結び付くため）。名前を変えたら、「意見」シートの「論点」列も同じ名前に置き換えてください。データの点検に「論点名が一致しない意見」として出ます。

記入者属性を変える

「属性マスタ」シートで行います。使わなくなった属性は行を消さず「有効」の ○ を外し、表示の順は「並び順」で変えます。変えたら omfy → 6 でフォームに反映します。

会合やゲストの話を意見として入れる

会合の記録から意見を起こすときは、モデレータが「意見」シートに直接書きます（メモのままではサイトにも Kumu にも出ないため）。

だれの発言かハンドル記入者属性・補足
ゲスト・講師・外部団体ゲスト意見話の中身に合う属性（例: 研究・教育・技術）。補足に「2024-03-12 の会合でのゲストの情報提供より」など
メンバー（発言者は特定しない）omfy過去の議論（-2026/10）「その他（自由記述）」など。補足に「○月○日の会合より」
  • この 2 つのハンドルはフォームの選択肢に出ません（モデレータ専用）。
  • 言い換えて短くまとめて構いません。別の人と思われる発言は別の行にします。
  • 実名、会合の予算・運営・資金の話は入れません。
  • 記入日は、会合の日付にします（自動で入った日付を書き換える）。

削除・訂正の申請に応える

申請は、GitHub の Issues か、メンバー経由で届きます。本人（未成年は保護者も）からの申請には、すぐに対応します。

  1. 申請の対象の行を特定する（記入日・ハンドル・主張の書き出しで探す）
  2. 訂正なら行を直す。削除なら行を削除する（行ごと削除し、空の行を残さない）
  3. 「変更履歴」シートに 1 行残す（個人が分かることは書かない）
  4. 数分後にサイトから消えたことを確かめ、申請した人に知らせる
  5. 個人情報が含まれていた場合は、技術担当に GitHub の控え（過去の版）の削除を頼む

メニュー使うとき
1. 入力規則（プルダウン）を設定▼が消えた、選べない値が入るようになったとき
2. 条件付き書式を設定赤く出るはずのセルが赤くならないとき
3. Kumu 用の数式を再生成論点の行を足した・消したあと。フォームの選択肢も一緒に更新する
4. シートの保護を設定モデレータが変わったとき（スクリプト先頭の MODERATOR_EMAILS を直してから）
5. 意見フォームを作成初回だけ。作り直すと古いフォームは受け付けを止め、URL が変わる（common.js の FORM を貼り直して push が必要）
6. 意見フォームの選択肢を更新論点・ハンドル・属性を足したあと、すぐ反映したいとき
意見フォームのリンク情報を表示フォームの URL と論点の項目番号をもう一度見たいとき
意見フォームの診断・取りこぼしの回収フォームで送ったのにシートに入っていないとき。シートに無い回答を一覧にし、まとめて書き写す
7. 自動更新（1 時間ごと）を設定／停止共有アカウントで 1 回だけ実行してある。もう一度押すと止まるので、ふだんは押さない
設定の確認迷ったらまずこれ。足りない設定があれば、実行すべきメニューの番号を出す

メニューの 5 と 7 は、共有アカウントで実行してください。個人のアカウントで実行すると、トリガーが個人のアカウントに付き、フォームも開けません。「設定の確認」でどのアカウントの設定かが分かります。

困ったとき

症状よくある原因対処
サイトに「データの取得に失敗しました」シートのウェブ公開が外れたシートの「ファイル → 共有 → ウェブに公開」で 3 枚をもう一度 CSV で公開する。公開し直しても URL は変わらない
書いた意見がサイトに出ない公開 CSV の反映待ち5 分ほど待って再読み込み。直後は古い版が返ることがある
フォームで送ったのにシートに無い書き写しの失敗（タブ名の変更など）原因を直してから 意見フォームの診断・取りこぼしの回収。回答はフォーム側に残っている
フォームに新しい論点・ハンドルが無い選択肢が古いomfy → 6（1 時間待てば自動でも直る）
Kumu に新しい論点が出ない／意見数が合わないKumu 用の数式が古いomfy → 3 のあと、Kumu のページを開き直す
▼が消えた、赤くならないシートの貼り付け・並べ替えで規則が壊れたomfy → 1 と 2、そのあと 設定の確認
書いた意見の論点が地図に結び付かない論点名の変更・表記ゆれ詳細ビューの「データの点検」で該当の意見を探し、「論点」列を正しい論点名に直す
共有アカウントに「トリガーの失敗」メール書き写し・自動更新が止まったメールのエラー内容を確かめ、直したら 設定の確認 と 取りこぼしの回収
毎晩の控えが失敗している公開 CSV が一時的に取れない公開 CSV の URL をブラウザで直接開いて取れるか確かめる。取れなければ「ウェブに公開」を確認

サイトを直すとき

  1. リポジトリの最新を取得し、site/ と README だけを直すdata/latest/ は毎晩 Actions が書き換えるので、手では触らない。
  2. 手元で確かめる: リポジトリ直下で python -m http.server を実行し、ブラウザで http://localhost:8000/site/ を開くファイルを直接開く（file://）と CSV の取得に失敗する。
  3. コミットして push する数分で GitHub Pages に反映。公開 CSV の URL を変えるときは site/common.js の先頭だけ直す。
  4. 画面の見た目を変えたら、ガイドのカードの画像（site/assets/view-*.webp）を撮り直す

このマニュアル自体もリポジトリの site/ にあります。他のページからリンクしないでください（限定公開のため）。手順や画面が変わったら、ここも直して最終更新の日付を変えます。

FAQ.

よくある質問

意見は何件書いてもいいですか？

何件でも構いません。1 件に 1 つの主張にして、言いたいことが複数あれば分けて書いてください。同じ論点に、違う属性の立場から書くのも歓迎です。

他の人の意見に反論したいときは？

相手の行には書き込まず、同じ論点に自分の意見を 1 件書いてください。補足に「○○さんの意見（記入日）への応答」と書くと、読む人がつながりを追えます。

書きたい論点が見つかりません。

いちばん近い上の論点に書き、補足に「新しい論点の提案: ○○」と書いてください。または、モデレータに論点の追加を頼んでください。俯瞰ビューのキーワード検索も使えます。

記入者属性に自分の立場がありません。

「その他（自由記述）」を選び、補足に具体的な立場を書いてください。同じ声が増えたら、モデレータが属性を足すことを検討します。

立場を決めきれません。

「条件付き」か「問い」を選んでください。条件付きなら「何がそろえば賛成か」を、問いなら「何が分からないのか」を主張に書きます。

「ゲスト意見」「omfy過去の議論」の意見は何ですか？

「ゲスト意見」は会合のゲスト・講師の話を、「omfy過去の議論」は過去の会合での議論を、モデレータが意見として起こしたものです。

フォームで「ログインが必要」と出ます。

意見フォームは、なりすましを防ぐために Google アカウントでのログインが必要です。シートの共有を受けたアカウントでログインしてください。アカウントが無い場合は技術担当に相談してください。
